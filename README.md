# Chain Health Bot

Telegram-бот для ротации велосипедных цепей: ведёт журнал поездок, считает пробег цикла активной
цепи и общий пробег каждой цепи, подсказывает, когда пора менять цепь, и присылает напоминания,
если цикл превышен, а ротация не сделана.

## Стек

Python 3.12+, [aiogram 3](https://docs.aiogram.dev/), [dishka](https://github.com/reagento/dishka)
(DI), SQLAlchemy 2 (async) + SQLite, Alembic, [uv](https://docs.astral.sh/uv/).

Архитектурные решения и их обоснование — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Настройка

1. Установи зависимости:

   ```bash
   uv sync
   ```

2. Скопируй `.env.example` в `.env` и заполни:

   ```bash
   cp .env.example .env
   ```

   - `BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather).
   - `ADMIN_IDS` — твой Telegram id (через запятую, если админов несколько). Админ может
     выполнять `/allow` и `/invite`, а сам получает доступ к боту без allowlist.
   - `DB_PATH` — путь к файлу SQLite (по умолчанию `data/chain_health.db`).
   - `REMINDER_TIME`, `TZ` — время и часовой пояс ежедневных напоминаний.

3. Установи pre-commit хуки:

   ```bash
   uv run pre-commit install
   ```

## Запуск локально

Миграции применяются автоматически при старте.

```bash
uv run python -m chain_health
```

## Тесты и линт

```bash
uv run pytest
uv run ruff check .
uv run ruff format .
```

Тесты покрывают сервисный слой (ротация, счётчики пробега, коррекция поездок, allowlist,
инвайты, выборка напоминаний), схему миграций, DI-граф и юнит-коммит/роллбэк, и телеграм-хэндлеры
целиком — через `tests/bot_harness.py`, гоняющий настоящий `Dispatcher` по сфабрикованным апдейтам.
Ручной чек-лист ниже остаётся нужен для того, что не проверить без реального Telegram API
(реальные сетевые ошибки, поведение клиента).

## Docker

Бот рассчитан на постоянную работу на домашнем сервере через long polling — публичный адрес не
нужен.

```bash
docker compose up -d --build
```

SQLite-файл сохраняется в `./data` на хосте (volume). Логи — `docker compose logs -f`.

## Как устроен доступ

Бот **молчит** в ответ незнакомым пользователям — никакого спам-списка заявок. Работает только в
личных чатах (в группах — тоже полная тишина). Чтобы пустить друга:

- `/invite` (только админ) — одноразовая ссылка вида `t.me/<bot>?start=<code>`, действует 48
  часов. Друг переходит по ней и сразу попадает в allowlist.
- `/allow <telegram_id>` (только админ) — ручное добавление по id.

Каждый пользователь видит и меняет только свои группы/цепи/поездки — сервисный слой проверяет
владение на каждой операции (см. `docs/ARCHITECTURE.md`, D15).

## Ручной чек-лист (e2e)

Прогони на тестовом токене перед деплоем на прод:

- [ ] `/start` → мастер онбординга создаёт первую группу и цепь.
- [ ] Отправка числа → пробег падает на активную цепь; в ответе видно группу/цепь/цикл.
- [ ] Reply-клавиатура (📊 Статус / ☰ Меню) с плейсхолдером и закреплённое сообщение-статус
      появляются и обновляются после ввода пробега.
- [ ] Лимит цикла выставлен маленьким (например, 10 км) → при превышении приходит
      предупреждение с кнопкой ротации.
- [ ] Ротация: рекомендованная цепь подсвечена, после подтверждения цикл новой цепи обнулён,
      у старой сохранена история.
- [ ] Коррекция поездки (☰ Меню → 📜 Последние поездки) — изменение и удаление пересчитывают
      счётчики.
- [ ] Вторая группа создаётся, переключение текущей группы работает, ввод пробега падает на
      верную группу.
- [ ] `/invite` со второго Telegram-аккаунта — по ссылке доступ выдаётся; третьему аккаунту без
      ссылки бот не отвечает.
- [ ] `REMINDER_TIME` выставлен на +2 минуты от текущего времени — приходит напоминание о
      превышенном цикле.
- [ ] Рестарт контейнера (`docker compose restart`) — данные, allowlist и закреплённое
      сообщение сохраняются.
- [ ] Сообщение в групповом чате, где есть бот, — полная тишина (бот работает только в личке).
- [ ] Со второго Telegram-аккаунта (допущенного через `/invite`) нажать инлайн-кнопку из чата
      первого аккаунта — вежливый отказ «не нашёл», чужие данные не показаны.
- [ ] Списать цепь, затем нажать старую кнопку «цепь» на неё — карточка цепи открывается с
      пометкой «(списана)», без трейсбека, спиннер Telegram гаснет. (Кнопка реально устаревает
      только если сама цепь удалена или id не существует — тогда ответ «не нашёл».)

## Интеграции (этап 2)

В MVP есть только архитектурный задел: у записи поездки — поля `source`/`external_id`, а
протокол `MileageSource` (`chain_health/domain/ports.py`) и пустой реестр источников в DI —
точка расширения для Strava/Garmin Connect/Komoot. Ручной ввод остаётся приоритетным: любое
значение, откуда бы оно ни пришло, можно исправить вручную. Что именно не решено (курсоры,
хранение токенов, идемпотентная вставка) — см. `docs/ARCHITECTURE.md`, D13.
